## 一、上下文窗口核心问题

### 1.1 窗口大小限制现状

| 模型 | 角色 | 上下文窗口 | Token上限 |
|------|------|-----------|---------|
| MiniMax-M2.7 | 狄仁杰 | ~1M | 约100万Token |
| DeepSeek | 李元芳 | ~128K | 约12.8万Token |
| 智谱GLM-4 | 宋慈 | ~128K-1M | 约12.8-100万Token |

> **关键矛盾**：三司会审中，狄仁杰（主持）窗口最大，李元芳和宋慈作为执行者窗口反而较小，容易成为瓶颈。

### 1.2 Token消耗的主要来源

```
Token消耗排名（从高到低）：
1. 系统提示词（SOUL.md / AGENTS.md 等）— 每次调用都加载，约占 3-10K
2. 完整对话历史 — 最消耗，随对话长度线性增长
3. 工具返回结果 — API返回内容，特别是代码/文件内容
4. 知识库/记忆文件 — 读取大型文件时
5. 模型输出 — 较少，约占输入的10-20%
```

### 1.3 上下文溢出的影响

- **截断（Truncation）**：旧对话被丢弃，导致模型"失忆"
- **推理质量下降**：早期关键信息被覆盖
- **指令跟随能力减弱**：模型更关注最近的内容
- **输出不一致**：同样的问题产生不同答案

## 二、现有优化方案

### 2.1 KV Cache / Attention 优化
- **原理**：缓存已计算的Key-Value对，避免重复计算
- **收益**：降低推理计算量，但不影响Token消耗
- **适用层**：模型推理层，用户侧无法直接控制

### 2.2 上下文压缩技术
- **原理**：将长上下文压缩为语义等价的短表示
- **代表性技术**：
  - LLMLingua / DeepPocket 等Prompt压缩工具
  - 选择性注意力（Selective Attention）
- **收益**：减少输入Token数，降低成本和延迟

### 2.3 RAG（检索增强生成）
- **原理**：外部向量数据库检索相关内容，按需注入上下文
- **收益**：突破固定窗口限制，支持超大规模知识
- **挑战**：需要额外的检索系统，引入延迟

### 2.4 记忆分层机制
- **原理**：将记忆分为不同层级（工作记忆/情景记忆/长期记忆）
- **典型做法**：
  - 工作记忆：保留最近N条对话
  - 情景记忆：保存关键事件摘要
  - 长期记忆：写入文件，按需读取
- **收益**：最大化利用有限窗口

## 三、三司会审实际情况分析

### 3.1 当前窗口配置

根据三司会审架构，三个模型的上下文窗口：
- **狄仁杰（MiniMax-M2.7）**：1M级，三司中最宽裕
- **李元芳（DeepSeek）**：128K，相对较小
- **宋慈（智谱GLM-4）**：128K-1M，中等

### 3.2 最消耗Token的操作

```
三司会审Token消耗排行榜：
🔴 极高消耗：
   - 读取大型记忆文件（MEMORY.md / daily logs）
   - 读取知识库文件
   - 完整工具执行日志回传

🟠 高消耗：
   - 系统提示词加载（SOUL.md + AGENTS.md ≈ 8-15K tokens）
   - 工具返回的长输出（如代码生成、文件内容）

🟡 中等消耗：
   - 正常对话历史
   - 任务指令描述
```

### 3.3 当前工作流的浪费点

1. **每次启动都加载完整系统提示词** — AGENTS.md + SOUL.md ≈ 8-15K tokens，开局即消耗
2. **无差别的对话历史** — 对话中大量无意义的寒暄/确认也计入Token
3. **工具输出不做摘要** — 一次文件读取返回全量内容
4. **无分层记忆机制** — 全部塞进上下文，不分层

## 四、立即可落地的优化方案（3-5个）

### 方案一：系统提示词最小化 + 动态加载

**原理**：将系统提示词拆分为"常驻核心（约2-3K）"和"按需加载（知识/技能约5-10K）"，核心提示词每次加载，扩展内容只在需要时注入。

**收益**：
- 每次请求节省 5-10K tokens
- 对于每天100次调用 → 节省 500K-1M tokens/天
- 降低延迟（尤其DeepSeek窗口较小）

**实施难度**：⭐（低）
- 拆分现有SOUL.md / AGENTS.md为常驻+模块
- 使用文件引用机制，按需读取扩展内容
- 无需修改模型或API

**具体做法**：
```
常驻核心（约2-3K tokens）：
  - 角色定位（三司架构）
  - 核心行为准则
  - 当前会话关键状态

按需加载模块：
  - skills/SKILL.md（需要时读取）
  - memory/长期记忆（按需检索）
  - 知识库文档（按需读取）
```

---

### 方案二：对话历史摘要化（Conversation Summarization）

**原理**：当对话历史超过阈值（如50条），自动触发摘要，将多轮对话压缩为关键要点摘要，替换原始历史。

**收益**：
- 将100条对话（假设每条约100 tokens）从10K → 压缩至约1K
- 节省约90%的历史Token消耗
- 保持长期任务上下文连贯性

**实施难度**：⭐⭐（中低）
- 需要定期触发摘要逻辑
- 关键信息不能遗漏（需要精心设计摘要提示词）
- 可在每次任务完成后/开始前执行摘要

**具体做法**：
```
触发条件：对话历史 > 50条 或 Token估计 > 30K
执行时机：
  - 任务切换时
  - 每日开始时
  - 显式请求时

摘要提示词：
  "将以下对话压缩为3-5个关键要点，保留所有决策、结论和待办事项"
```

---

### 方案三：工具输出截断 + 关键信息提取

**原理**：对于工具返回的长输出（如文件内容、代码执行结果），不直接塞入上下文，而是先提取关键信息。

**收益**：
- 文件读取场景：100行代码 → 关键5行 ≈ 节省95% tokens
- 工具调用返回：完整JSON → 结构化摘要 ≈ 节省60-80% tokens
- 减少上下文污染，提升模型聚焦能力

**实施难度**：⭐⭐（中）
- 需要在工具层增加后处理逻辑
- 需要对不同工具类型设计不同的提取策略
- OpenClaw的工具层可以扩展

**具体做法**：
```
文件读取类工具：
  - 策略1：限制返回行数（默认前100行 + 后50行）
  - 策略2：先问模型"需要哪部分"，再精确读取
  - 策略3：正则/关键词提取关键段落

代码执行类：
  - 只返回stdout/stderr的关键行
  - 截断重复/调试输出
  
API返回类：
  - JSON结构化提取，只保留必要字段
  - 错误信息完整保留，成功结果精简摘要
```

---

### 方案四：知识库向量检索（RAG）

**原理**：将常用知识（MEMORY.md、长期记忆、工作流程文档）存入向量数据库，按需检索注入，而非每次全量加载。

**收益**：
- 支持超大规模知识（不受窗口限制）
- 只注入相关内容，减少噪声
- 适合知识密集型任务

**实施难度**：⭐⭐⭐（中等）
- 需要部署向量数据库（Chroma / FAISS / Qdrant）
- 需要Embedding模型
- 知识库需要定期更新索引

**具体做法**：
```
知识来源：
  - MEMORY.md（长期记忆）
  - 工作流程文档
  - 技能文档（SKILL.md）
  - 每日日志摘要

检索流程：
  1. 任务来了 → 提取查询向量
  2. 向量数据库检索Top-5相关段落
  3. 注入上下文（<5K tokens）
  4. 模型回答

适用场景：
  - 需要调用历史决策/经验时
  - 跨长周期任务（超过1周）时
  - 技能文档查询时
```

### 方案五：分层记忆 + 选择性遗忘

**原理**：建立明确的记忆层级制度，让不同类型的信息进入不同的"存储层"，上下文窗口只保留最高价值的"工作记忆"。

**收益**：
- 最大化利用有限窗口
- 防止低价值信息驱逐高价值信息
- 系统性解决"上下文溢出"问题

**实施难度**：⭐⭐（中低）
- 需要建立明确的记忆分类标准
- 需要定期执行记忆归档/清理
- 关键是执行纪律（不能什么都往工作记忆塞）

**具体做法**：
```
三层记忆架构：

  ┌─────────────────────────────────────┐
  │ L1 工作记忆（Working Memory）        │  ← 当前上下文（<50K tokens）
  │   - 当前任务指令                      │
  │   - 最近10条关键对话                  │
  │   - 正在执行的任务状态                 │
  └─────────────────────────────────────┘
  ↓ 定期归档（任务完成 / 对话结束）
  
  ┌─────────────────────────────────────┐
  │ L2 情景记忆（Episodic Memory）       │  ← 存在文件（无硬性限制）
  │   - 今日重要事件摘要                  │
  │   - 已完成任务结论                    │
  │   - 重要决策记录                      │
  └─────────────────────────────────────┘
  ↓ 定期沉淀（每周 / 每月）
  
  ┌─────────────────────────────────────┐
  │ L3 长期记忆（Long-term Memory）      │  ← MEMORY.md（长期积累）
  │   - 核心偏好/习惯                     │
  │   - 方法论沉淀                        │
  │   - 重要关系/资源信息                 │
  └─────────────────────────────────────┘

记忆流转规则：
  - 每任务结束 → 工作记忆归档至情景记忆
  - 每周末 → 情景记忆提炼至长期记忆
  - 长期记忆超过阈值 → 提炼压缩
```
