**当前架构：**
- 热(30m) / 温(12h) / 冷(1d) / 周(7d) / 永久
- 问题：层级太多，cron维护成本高，实际执行不到位

**建议简化：**
```
热记忆 → hot-1h.md（30分钟，实时更新，主session维护）
温记忆 → warm-12h.md（每日日志替代，cron+主session维护）
永久记忆 → MEMORY.md（精简版，重大事件更新）
知识库 → knowledge/（结构化文档积累）
```

**核心原则：**
- 记忆层级越少越好执行
- 宁可2层执行到位，不要5层都半吊子
- 每次更新都要问：这个信息值得保留吗？
