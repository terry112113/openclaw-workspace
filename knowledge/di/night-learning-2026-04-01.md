**现状：** L4进化在2026-03-31三司会审已裁决，5个待执行任务全部停在"⏳"。

| 待执行任务 | 根因 |

---

## 二、精准意图定义

**L4最终状态是什么？**

> L4 = 任务执行后，自动捕获反思 → 存储到结构化位置 → 跨Agent可见 → 反哺下一次执行

与L3的本质区别：
- L3：完成即结束
- L4：完成触发捕获，捕获驱动下一次更好

## 三、五个机制具体规格

### 机制1：反思触发机制（魏征主导）

**触发条件（二选一）：**
1. 自动触发：每个cron任务完成后 → 立即写入反思
2. 手动触发：每次主动任务完成后 → HEARTBEAT.md反射查

**触发后输出到的文件：**
```
knowledge/di/lessons/[YYYY-MM-DD]-[任务名].md
```

**反思输出格式（反思三问 + 元数据）：**
```markdown
# 反思：[任务名]
> 日期：2026-04-01 | 触发：[cron/手动] | 执行人：魏征

## 本轮哪条有效？
[具体描述]

## 哪条失效，原因？
[具体描述 + 根因分析]

## 下轮如何改进？
[可执行的具体行动，不超过3条]
```

**cron集成方案：**
- 在每个cron任务的指令末尾追加"执行完毕后填写反思到knowledge/di/lessons/"
- 或新建一个"反思守护cron"，每30min检查当日新完成任务触发

**实施检查点：**
- [ ] `knowledge/di/lessons/` 目录存在
- [ ] 反思模板文件已创建
- [ ] cron任务末尾已追加反思指令

### 机制2：跨Agent情报共享（李元芳主导）

**核心约束：Agent是ephemeral（临时），无法主动推送。**

**解决方案：共享知识目录 + 读取协议**

**目录结构：**
```
knowledge/shared/
  di-lessons/        # 狄仁杰反思存档
  shensi-lessons/    # 李元芳反思存档
  wei-lessons/       # 魏征反思存档
  weekly-aggregate/  # 周汇总（周五生成）

```

**写入协议：**
- 每当反思触发 → 写入对应 lessons/ 目录
- 不覆盖旧文件，每次新增一个

**聚合协议（周五cron驱动）：**
- cron时间：每周五 18:00
- 执行人：狄仁杰（主持读取三方文件）
- 输出：写入 `knowledge/shared/weekly-aggregate/YYYY-WXX.md`

**周五汇总输出格式：**
```markdown
# 三司会审本周经验汇总
> 日期：2026-04-04（周五）| 汇总人：狄仁杰

## 本周最有效的1件事

## 本周教训（3条）
| 来自 | 教训 | 可复用场景 |
|------|------|----------|
| 魏征 | ... | ... |

## 下周重点
[基于本周反思的主动优化方向]
```

**读取协议（每个session开始时）：**
- 读取当周汇总：`knowledge/shared/weekly-aggregate/YYYY-WXX.md`
- 若无汇总 → 读最近一份汇总

### 机制4：价值分层标准化（魏征主导）

**三层锚点分类：**

| 层级 | 定义 | 示例 | 注入方式 |
|------|------|------|---------|
| P0 | 跨所有会话，定义身份 | SOUL.md身份、核心约束、皇上密码 | 每次session自动读入context |
| P1 | 当前项目，7天有效 | 当前Sprint目标、活跃任务、活跃问题 | 每次session读P1文件 |
| P2 | 单次任务，一次性 | 某个具体调试任务的目标 | 任务开始时注入，结束即清除 |

**锚点文件位置：**
```
knowledge/anchors/
  p0-always.md       # P0锚点（每次session开头读）
  p1-weekly.md       # P1锚点（每周一更新）
  p2-[taskname].md   # P2锚点（按需创建）
```

**P0锚点内容（必须手动维护）：**
```markdown
# P0锚点 - 永久有效
> 最后更新：2026-04-01

## 身份
- 狄仁杰，大理寺卿，主持三司会审
- 三权平等：狄仁杰裁决/李元芳情报/魏征技术

## 核心约束
- 路径禁用中文
- 三司会审三回合不得跳过
- 学习必须有产出（≥50字）

## 关键配置
- 飞书大群ID：oc_7ff140c90bcdd119a6ddc59610c30829
- 皇上密码：427521427521tan
```

**P1锚点更新频率：每周一9:00 cron驱动**

**注入协议：**
1. 每次session开始 → 读 p0-always.md
2. 每次session开始 → 读 p1-weekly.md（若存在且未过期）
3. 任务开始 → 读对应 p2-[taskname].md
4. 任务结束 → p2文件可删除或归档

**实施检查点：**
- [ ] `knowledge/anchors/` 目录及三个锚点文件创建
- [ ] P0锚点内容填充

### 机制5：上下文复用机制（李元芳主导）

**注入点：session启动流程（AGENTS.md规定）**

**注入逻辑：**
```
Session启动
  → 读 SOUL.md + USER.md + CURRENT.md（现有）
  → 读 P0锚点（新增）
  → 若有当周汇总 → 读当周汇总（新增）
  → 若有活跃P1锚点 → 读P1（新增）
  → 开始任务
```

**注入不是复制，是读取后自然融入上下文。**

**避免上下文污染：**
- P2锚点只在任务开始时注入，任务结束即释放
- P0锚点保持精简（≤200字核心内容）
- P1锚点保持精简（≤300字）

**RAG召回质量（魏征设计）：**
- 每次检索anchors时，记录"是否有用"
- 有用 → 下次同类任务优先召回
- 无用 → 降低该锚点权重

**实施检查点：**
- [ ] AGENTS.md session启动流程已更新
- [ ] P0/P1锚点文件已就位
- [ ] RAG质量反馈机制已记录（简单日志即可）

## 四、L4进化核心闭环

```
┌─────────────────────────────────────────────┐
│  L4核心闭环                                  │
│                                             │
│  [执行任务]                                  │
│      ↓                                       │
│  [反思触发] → 写入 lessons/                  │
│      ↓                                       │
│  [心跳检查] → 读取 lessons/ → 提炼到心跳    │
│      ↓                                       │
│  [周五汇总] → 三方 lessons → 周汇总          │
│      ↓                                       │
│  [锚点分层] → P0/P1/P2 → 注入下一session     │
│      ↓                                       │
│  [上下文复用] → 下一session读取锚点          │
│      ↓                                       │
│  [更好执行] → 回到"执行任务"                 │
└─────────────────────────────────────────────┘
```

**L4 vs L3的本质区别：**

| 维度 | L3 | L4 |
|------|----|----|
| 任务完成 | 结束 | 开始（反思捕获） |
| 学习 | 被动（人类触发） | 自动（触发机制） |
| 跨任务 | 无记忆传递 | 锚点注入 |
| 跨Agent | 独立 | 共享 lessons |
