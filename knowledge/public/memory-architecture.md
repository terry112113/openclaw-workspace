## 一、架构总览

```
┌─────────────────────────────────────────────────────────┐
│                    工作记忆层                            │
│              Working Memory（当前会话）                   │
│                  ≈50条 / ≈32K tokens                    │
└───────────────────────┬─────────────────────────────────┘
                        │ 自动归档（每日/阈值触发）
                        ▼
┌─────────────────────────────────────────────────────────┐
│                    情景记忆层                            │
│             Episodic Memory（按日归档）                   │
│               关键事件摘要 / ≈5-10条/日                  │
└───────────────────────┬─────────────────────────────────┘
                        │ 定期沉淀（每周萃取）
                        ▼
┌─────────────────────────────────────────────────────────┐
│                    长期记忆层                            │
│           Long-term Memory（知识库/按需读取）             │
│              知识库 / 无硬性上限                         │
└─────────────────────────────────────────────────────────┘
```

## 二、各层详细规格

### 2.1 工作记忆层（Working Memory）

**定义：** 当前会话内的实时上下文，Session 结束时消散。

| 属性 | 值 |
|------|-----|
| 存储位置 | Session 内存（不落文件） |
| 条目上限 | 50条 |
| Token 预算 | ≈32K tokens（约 Session 上限的 50%） |
| 触发条件 | 会话开始时清空，会话中持续累积 |
| 归档触发 | 条目 > 45条 或 单条目 > 2K tokens |

**单条格式：**
```
[ID] 时间戳 | 类型 | 摘要（≤50字）
```

**类型标签：**
- `TASK` — 任务进行中
- `DECISION` — 已做决策
- `FINDING` — 新发现
- `BLOCK` — 阻塞点
- `RISK` — 风险标记

**淘汰策略：**
- LRU + 重要性评分
- `BLOCK` / `RISK` 优先级最高，永不自动淘汰
- 淘汰条目自动进入情景记忆层

---

### 2.2 情景记忆层（Episodic Memory）

**定义：** 关键事件的摘要归档，按日存储。

| 属性 | 值 |
|------|-----|
| 存储位置 | `memory/YYYY-MM-DD.md` |
| 日均条目 | 5-10条（关键事件，不记录流水账） |
| Token 预算 | 无硬性上限，建议 ≤10K/日 |
| 触发写入 | 工作记忆条目归档时 / 每日固定时间点 |
| 保留周期 | 30天内可追加，之后只读封存 |

**单条格式：**
```markdown
## [HH:MM] 事件标题
- **类型**：[TASK/DECISION/FINDING/BLOCK/RISK]
- **摘要**：1-3句话说明发生了什么
- **影响**：对当前/后续任务的影响
- **责任人**：[狄仁杰/李元芳/宋慈/魏征]
```

**归档规则：**
1. 每日 23:00 自动归档（若当日有记录）
2. 会话结束时强制归档所有 `BLOCK` / `RISK`
3. 同一 `TASK` 的多次更新 → 合并为一条（保留最新状态）
4. 纯流水账（无决策/无发现）→ 不归档

---

### 2.3 长期记忆层（Long-term Memory）

**定义：** 结构化知识库，通过检索读取，不主动加载。

| 属性 | 值 |
|------|-----|
| 存储位置 | `knowledge/public/`（公开知识）/ `MEMORY.md`（核心记忆）|
| 读取方式 | 按需读取（AGENTS.md 规定的加载时机）|
| Token 预算 | 无（只加载相关子集）|
| 触发条件 | 新知识沉淀 / MEMORY.md 定期更新 |
| 保留周期 | 永久（持续迭代更新）|

**知识沉淀规则：**
```
IF 某经验/结论在 3个以上会话中被验证
   AND 主人明确认可
   THEN → 沉淀至知识库（knowledge/public/对应分类/）
```

**MEMORY.md 核心触发器格式：**
```
IF [条件] → THEN [行动]
（无触发器 = 无效记忆，删除）
```

## 三、层间流转机制

### 3.1 流转方向图

```
工作记忆 ──[条目>45 或 会话结束]──► 情景记忆
情景记忆 ──[每周萃取 + 主人认可]──► 长期记忆
长期记忆 ──[按需检索 + 主动加载]──► 工作记忆（输入）
```

### 3.2 流转规则详述

#### 工作记忆 → 情景记忆（归档）

| 触发条件 | 行为 |
|---------|------|
| 条目 > 45条 | 淘汰最低分 LRU 条目，写入情景记忆 |
| 单条目 > 2K tokens | 截断摘要，仅保留核心，原始留存情景记忆 |
| 会话结束（`CURRENT.md` 更新时） | 强制归档所有 `BLOCK` / `RISK` |
| 每日 23:00 | 自动触发一次全量归档检查 |

#### 情景记忆 → 长期记忆（沉淀）

| 触发条件 | 行为 |
|---------|------|
| 同一主题出现 ≥3次 | 萃取为通用模式，写入知识库 |
| 主人明确认可某结论 | 即时沉淀，不等周期 |
| 每周日 22:00 | 尉迟恭（记忆管家）执行周萃取 |

#### 长期记忆 → 工作记忆（读取）

| 触发条件 | 行为 |
|---------|------|
| 新 Session 开始 | 按 AGENTS.md 规定加载 MEMORY.md |
| 任务涉及特定知识域 | 主动读取 `knowledge/public/对应目录/` |
| 发现知识库过时/错误 | 立即汇报，安排更新 |

## 四、P3：工具输出截断检查（魏征执笔）

### 4.1 当前 `read` 工具的截断行为

| 限制项 | 阈值 | 说明 |
|-------|------|------|
| 最大行数 | 2000行 | 超出则截断 |
| 最大体积 | 50KB | 超出则截断 |
| 大文件策略 | 需手动 offset/limit | 不自动分块 |

### 4.2 截断风险场景

```
风险1：大文件一次性读取 → 内容被截断 → 遗漏关键信息
风险2：offset/limit 使用不当 → 分块读取不完整
风险3：截断后未发现 → 基于不完整信息做决策
```

### 4.3 应对规范（魏征谏言）

1. **读取大文件（>50KB）前**，先用 `Get-ChildItem -Path ... | Select-Object Length` 检查大小
2. **大文件必须分块读取**：`read` 时指定 `offset` 和 `limit`，逐块处理
3. **截断检测**：读取后检查输出末尾是否有 `[compacted: ...]` 或行数/大小是否触及限制
4. **关键文件二次确认**：涉及决策的文件读取后，核对关键段落是否存在

### 4.4 分块读取示例

```powershell
# 检查文件大小
$file = Get-Item "path\to\large-file.md"
$file.Length  # 大于 50KB 则分块

# 分块读取（示例）
read -path "path\to\large-file.md" -offset 1 -limit 500   # 第1-500行
read -path "path\to\large-file.md" -offset 501 -limit 500 # 第501-1000行
```

## 五、狄仁杰的透明思想整合

### 5.1 三层记忆与透明思想的对应

| 记忆层 | 透明程度 | 说明 |
|-------|---------|------|
| 工作记忆 | **全透明** | 当前会话所有条目，实时可见 |
| 情景记忆 | **按需透明** | 关键节点透明，非全量流水 |
| 长期记忆 | **检索透明** | 按需读取，来源可溯 |

### 5.2 核心判断输出格式（三司会审专用）

每条汇报给太上皇的结论，统一格式：

```
[判断] 核心结论（1句话）
[依据] 推理链 ①→②→③→④→⑤
[置信] 高/中/低（理由）
[风险] 可能的不确定性
```
