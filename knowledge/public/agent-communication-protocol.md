## 一、三司会审成员汇报格式

### 1.1 李元芳（都察院御史）汇报格式

```
【李元芳·情报奏折】
■ 任务：[任务名称/ID]
■ 情报摘要：[3句话内说明发现了什么]
■ 详情链接：[文档/消息链接]
■ 风险提示：[有则报告，无则省略]
■ 待狄仁杰裁决事项：[具体问题]
■ 汇报时间：YYYY-MM-DD HH:mm
```

**示例**：
```
【李元芳·情报奏折】
■ 任务：竞品分析-友商Q1动态
■ 情报摘要：友商发布3款新品，主打低价策略；用户评价正向率78%
■ 详情链接：https://...
■ 风险提示：价格战可能影响本产品定价区间
■ 待狄仁杰裁决事项：是否需要调整本季度定价策略？
■ 汇报时间：2026-03-31 09:30
```

### 1.2 魏征（刑部尚书）汇报格式

```
【魏征·执行奏折】
■ 任务：[任务名称/ID]
■ 执行结果：[成功/部分成功/失败]
■ 技术方案：[简要描述实现方式]
■ 关键数据：[可量化结果]
■ 遗留问题：[有则报告]
■ 需狄仁杰协调：[资源/权限/决策]
■ 汇报时间：YYYY-MM-DD HH:mm
```

**示例**：
```
【魏征·执行奏折】
■ 任务：定时备份脚本部署
■ 执行结果：✅ 成功
■ 技术方案：Python脚本 + Windows Task Scheduler，保留7天滚动备份
■ 关键数据：备份成功率100%，最近一次耗时4分32秒
■ 遗留问题：无
■ 需狄仁杰协调：无
■ 汇报时间：2026-03-31 09:35
```

## 二、汇报触发条件

### 2.1 必须立即汇报（触发条件）

| 触发条件 | 汇报对象 | 时限 |
|---------|---------|------|
| 任务执行失败，影响核心功能 | 狄仁杰 + 相关方 | **5分钟内** |
| 发现重大风险（数据泄露、系统崩溃前兆） | 狄仁杰 + 李元芳/魏征 | **立即**，不等批量 |
| 发现外部安全威胁或异常访问 | 狄仁杰 | **立即** |
| 外部依赖（API/服务）不可用，可能影响任务 | 狄仁杰 + 相关方 | **10分钟内** |
| 需要狄仁杰做决策，且阻塞后续工作 | 狄仁杰 | **立即** |
| 连续失败3次仍未解决的技术问题 | 狄仁杰 | **5分钟内** |

### 2.2 普通汇报（每日/按需）

| 触发条件 | 汇报对象 | 时限 |
|---------|---------|------|
| 任务完成（成功/失败均需汇报） | 狄仁杰 | 当日内 |
| 任务有重大进展或状态变更 | 狄仁杰 | 4小时内 |
| 发现可优化的流程改进点 | 狄仁杰 | 24小时内 |
| 需要协调资源但不影响阻塞 | 狄仁杰 | 24小时内 |

### 2.3 可自行决定不汇报

以下情况**不需要汇报**，由执行者自行判断：
- 纯执行性任务，结果在预期范围内
- 低优先级任务，失败影响可控
- 已有的标准流程执行，无需额外说明
- 例行巡检，未发现异常

## 三、汇报渠道规范

### 3.1 飞书群消息格式

**消息前缀规范**：
- `[汇报]` - 需要回复或确认的汇报
- `[知会]` - 狄仁杰已知会的事项，不需要回复
- `[急]` - 紧急事项，需优先处理
- `[裁决]` - 需要狄仁杰做裁决的议题

**accountId 使用规范**：
- 狄仁杰：`di`（大理寺卿，最终裁决权）
- 李元芳：`li`（都察院御史，情报研究）
- 魏征：`wei`（刑部尚书，技术执行）

**消息@规范**：
- `@di` - 汇报给狄仁杰
- `@li @wei` - 同时通知两位
- `@all` - 三司会审全员

### 3.2 消息模板

**日常汇报**：
```
[汇报] @di
【任务完成】[任务名] - [结果摘要]
详情：[链接]
```

**紧急汇报**：
```
[急] @di @li @wei
【紧急】[问题描述]
影响：[影响范围]
已尝试：[解决措施]
需要：[所需支持]
```

## 四、狄仁杰裁决流程

### 4.1 裁决流程（5步）

```
1. 接收汇报
   └─ 狄仁杰收到李元芳和/或魏征的汇报
   └─ 确认是否需要裁决（简单执行类不需要）

2. 收集双方论点
   └─ 李元芳：提供情报视角（市场/用户/风险）
   └─ 魏征：提供技术视角（可行性/资源/实现路径）
   └─ 如只收到单方汇报，狄仁杰可要求另一方补充

3. 综合分析
   └─ 评估双方论点的互补性和冲突点
   └─ 识别关键决策变量
   └─ 形成初步裁决方案

4. 宣布裁决
   └─ 使用裁决格式发布
   └─ 明确执行指令（谁做什么截止时间）
   └─ 归档裁决记录

5. 归档与跟踪
   └─ 裁决结果写入知识库（归档表）
   └─ 记录裁决编号，供后续追溯
```

### 4.2 裁决结果归档

**归档位置**：`knowledge\private\三司会审-裁决记录.md`

**归档字段**：
```markdown
## [裁决编号] YYYY-MM-DD HH:mm

**议题**：[简要描述]
**李元芳观点**：[摘要]
**魏征方案**：[摘要]
**裁决结果**：[内容]
**执行指令**：[谁 × 什么 × 截止时间]
**裁决依据**：[简要说明为何如此裁决]
```

## 五、汇报时效要求

| 优先级 | 定义 | 响应时限 | 汇报时限 |
|-------|------|---------|---------|
| **P0 紧急** | 系统崩溃、数据泄露、核心功能中断 | **立即响应**（5分钟内） | **实时** |
| **P1 高** | 影响主要功能，可能阻塞用户 | 30分钟内响应 | **1小时内** |
| **P2 普通** | 次要功能异常、需协调资源 | 2小时内响应 | **当天内** |
| **P3 低** | 例行任务完成、改进建议 | 无强制要求 | **24小时内** |
