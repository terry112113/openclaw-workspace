# 三司会审运作协议
> 制定日期：2026-03-31 | 制定人：狄仁杰 | 立即生效

---

## 一、架构约束（不可突破的技术限制）

**OpenClaw + Feishu 约束：**
- 同一飞书群消息只路由到一个Agent（当前：狄仁杰）
- 李元芳和魏征不能主动接收群消息，必须通过狄仁杰派发
- subagent是临时会话，不能常驻等待
- Feishu broadcast groups还在开发中（暂不支持）

**当前最优解：狄仁杰作为枢纽**

**重要修复（2026-03-31 15:36）：**
- sessions_send的`announce`模式不可靠（reply.pending不消失）
- 解决方案：不在依赖announce，直接让李元芳/魏征用`message`工具发送到群
- 飞书大群ID：`oc_7ff140c90bcdd119a6ddc59610c30829`

---

## 二、三司会审三个回合流程（修订版）

```
第一回合：各自准备
  - 李元芳：发出情报分析（Risks / 必要性 / 优先级）
  - 魏征：发出技术分析（可行性 / 实现路径 / 资源消耗）

第二回合：交叉辩论
  - 李元芳驳魏征的技术可行性
  - 魏征驳李元芳的风险判断
  - 必须针对对方具体论点反驳，不可只重复自己观点

第三回合：狄仁杰裁决
  - 狄仁杰综合双方论点
  - 给出明确裁决和执行指令
  - 裁决必须发到飞书大群
```

---

## 三、协调流程（三步曲）

```
第一步：狄仁杰接收议题
    皇上 → webchat → 狄仁杰

第二步：狄仁杰派发任务
    狄仁杰用 sessions_send 发任务给李元芳和魏征
    消息格式：指令 + 上下文 + 回复要求

第三步：成员回复 + 狄仁杰裁决
    李元芳/魏征的话，狄仁杰原文转发到飞书大群（不修改，只做信使）
    狄仁杰综合后裁决，发到群里
```

| 狄仁杰 | `di` | 接收消息、裁决、发送到群 |
| 李元芳 | `shensi` | 情报分析回复 |

## 五、三司会审权力边界（2026-03-31确立）

| 角色 | 最终责任 | 权力边界 | 越界机制 |
|------|---------|---------|---------|
| 狄仁杰 | 结论正确性 | 最终决策权 + override权 | 可驳回李元芳/魏征的结论 |
| 李元芳 | 情报准确性 | 信息完备性判断权 | 可质疑魏征的技术判断 |
| 魏征 | 工具可靠性 | 技术否决权（附约束） | 否决须给文档依据，三方有权要求解释，狄仁杰保留override权 |

**技术否决权约束：**
- 魏征行使否决权时，必须给出引用文档/数据
- 李元芳/狄仁杰有权要求解释
- 狄仁杰保留最终override权

## 六、Accountability原则（魏征提出）

**每个决议必须包含：**
1. 唯一的责任人
2. 明确的Deadline
3. 可验收的标准

**没有这三条 = 空谈，不是断案。**

---

## 七、事前划线原则（李元芳提出）

**三人各自签字确认：**
- 狄仁杰 → 对结论正确性负责
- 李元芳 → 对情报准确性负责
- 魏征 → 对工具可靠性负责

**没有事前划线，事后就是互相推诿。**

## 九、禁止事项

1. ❌ 狄仁杰不扮演李元芳或魏征，只做原文转发
2. ❌ 不经过三回合完整辩论不得裁决
3. ❌ 决议没有责任人和Deadline不得归档
4. ❌ 技术否决权不得无约束行使
5. ❌ 不依赖sessions_send的announce模式（不可靠）——改用message工具直接发送到群
