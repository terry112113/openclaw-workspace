## 一、当前问题

### 1.1 极高失效率 —— 11/19 = 57.9% 处于 error 状态

以下任务最近一次执行均为 error，且 run history **total:0**（说明启动即失败，无任何执行记录）：

| 任务 | 调度 | 问题 |
|------|------|------|
| 李元芳-A-晨间预热 6:00 | error | 6点太早，可能主环境未就绪 |
| 李元芳-B-午前研究 8:00 | error | 与"深度研究 7am"高度重叠 |
| 魏征-学习窗口A-07:00行业动态 | error | 启动失败 |
| 魏征-学习窗口B-09:00工具发现 | error | 启动失败 |
| 魏征-学习窗口C-12:00审计方法 | error | 启动失败 |
| 李元芳-深度研究 7,13,18点 | error | 启动失败 |
| 李元芳-每日学习skills.sh 9,15,21点 | error | 启动失败 |
| 魏征-每日下载10个skills 9:20 | error | 启动失败 |
| 李元芳-D-午后研究 14:00 | idle | 未触发（上游失败链） |
| 李元芳-F-晚间深度 19:00 | error | 启动失败 |
| 魏征-学习窗口F-20:00深度审计 | error | 启动失败 |
| 狄仁杰-每日Skills维护 10:00 | error | 启动失败 |

**核心原因：** 这11个任务全部 target 为 `isolated` + `minimax-sub/MiniMax` 模型，且 run history 为空。推测isolated子agent启动时报错（可能是模型路由配置问题），任务从未真正执行，每次都在烧API额度但产出了0价值。

### 1.2 时间撞车——重复任务

| 撞车组合 | 时间 | 问题 |
|----------|------|------|
| 李元芳-B-午前研究 8:00 + 李元芳-深度研究 7:00 | 前后脚 | 7点和8点做相似研究，浪费 |
| 李元芳-D-午后研究 14:00 + 李元芳-深度研究 13:00 | 连续小时 | 13点和14点重复 |
| 李元芳-A-晨间预热 6:00 + 深度研究 7:00 | 6/7点 | 6点太早，预热价值低 |

### 1.3 学习窗口6个——过度碎片化

魏征的6个学习窗口（A-F），每个消耗独立API调用，但：

- 主题相近（A行业动态/B工具发现/C审计方法实际上有重叠）
- 没有证据表明"碎片化多次"比"集中一次"效果更好
- **更关键的是：这6个任务全部处于 error 状态，1个都没跑起来**
- 即使修复后，6个窗口 = 每日6次API调用，成本是3个的2倍
